# Fijos · fundación + réplica de la vista principal — plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Dejar la vista principal de Fijos replicada pixel-perfect en el preview dev, en claro y oscuro, con sus 8 estados de hero y 6 de Avisos, lista para el gate de aprobación del owner. **No se cablea nada a datos reales en este plan.**

**Architecture:** Mismo patrón que Home/Gastos, ya validado dos veces en este repo: un módulo de tokens (`fijos-spec.ts`) + un kit presentational (`fijos-screen.tsx`) que exporta sub-componentes puros, alimentado por props desde una pantalla de preview con fixtures. Cero acceso a datos, cero hooks de red. El cableado vive en un plan posterior.

**Tech Stack:** React Native 0.81 (Fabric) · Reanimated v4 · react-native-skia (el Brot) · react-native-svg · vitest (env `node`, sin React renderer).

**Fuente de verdad:** `design/fijos-2026-07/` — `Fijos Manifiesto.dc.html` es la vista principal; `README.md` documenta tokens, estados y animaciones. Abrir el `.dc.html` en un browser para ver el resultado esperado.

## Global Constraints

- **Transcripción LITERAL del markup.** Es la regla del gate de aprobación de este proyecto: los valores (radios, sombras, gradientes, tamaños, pesos, gaps) se copian del `.dc.html`, no se "interpretan" ni se redondean a la escala de spacing de la app. Si un valor del mockup contradice un token existente, gana el mockup y se anota en el reporte.
- **`experimental_backgroundImage` acepta los strings CSS del mockup tal cual** — es como se portaron los gradientes de Home y Gastos. No convertir a `LinearGradient` salvo que el string falle.
- **Solo se animan `transform` y `opacity`.** Nunca `width`, `height`, `boxShadow` ni props de SVG.
- **`transform` siempre es un array**, nunca `undefined` (gotcha del proyecto: crashea iOS).
- **Duraciones y springs salen de `@/lib/motion`**; `npm run guard:motion-tokens` rechaza literales inline. Ese guard falla hoy por **26 violaciones PRE-EXISTENTES en 12 archivos ajenos** (billing, fijos, garden, count-up-text, use-border-glow, intro-slides, signup, asistente, achievements-gallery) — no son de este plan. Lo que importa es que los archivos nuevos NO aparezcan en su lista; verificarlo por `grep`, no a ojo.
- **Reduced motion manda:** `useReducedMotion()` incluye el heurístico de hardware (`deviceYearClass < 2020`). El README del handoff lo pide explícitamente para el ticker y el pulso.
- **Worklets sin `Intl` ni locale** (gotcha del proyecto: crashea sin stack).
- **`cancelAnimation` en cleanup** de todo shared value animado.
- **El kit lleva `// @i18n-ignore-file`** en la primera línea, como el de Gastos: la copy del mockup se transcribe literal en español y la i18n entra en el pase de cableado, no acá.
- **Commits acotados por ruta**, con `git add <ruta>` explícito. NUNCA `git add -A`, `git add .` ni `git commit -a`: la branch `feat/ui-redesign` tiene ~65 archivos sin commitear de tandas anteriores que no se deben tocar. **Y verificar el cierre de dependencias**: si un archivo nuevo importa otro que sigue sin commitear, HEAD deja de compilar desde un checkout limpio (pasó en el plan anterior). Después de cada commit, confirmar con `git show --stat HEAD`.
- **El bash tool no carga nvm:** `source ~/.nvm/nvm.sh` antes de cualquier `npx`/`npm`.

### Task 4: Kit — componente Avisos, con ticker y sus 6 estados

**Files:**
- Modify: `mobile/components/redesign/fijos/fijos-screen.tsx`

**Interfaces:**
- Consumes: lo de la Task 3.
- Produces: `FijosAvisos` + sus tipos.

- [ ] **Step 1: Transcribir la estructura**

Dos bloques bajo un título con pill de contador: **POR PAGAR · ESTE MES** (ticker horizontal de chips con dot de urgencia + nombre + monto + tag, con un punto "live" pulsante) y **AUMENTOS Y RECORDATORIOS** (filas con ícono de tendencia + fila-resumen de calendario). El Brot del componente reacciona al peor estado.

- [ ] **Step 2: El ticker**

El original es `@keyframes fijosTicker`, `30s linear infinite`, sobre una lista duplicada, con `mask-image: linear-gradient(90deg, transparent, #000 7%, #000 93%, transparent)` para el fade de bordes y ancho `max-content`.

Al portar:
- El desplazamiento es un `translateX` en el UI thread. La lista duplicada es lo que hace el loop sin costura: se mide el ancho de UNA copia y se anima de `0` a `−anchoDeUnaCopia`, reiniciando ahí — a esa altura la segunda copia está exactamente donde arrancó la primera.
- **La duración va a un token** de `@/lib/motion` (`decorativeDurations`, que es donde viven los loops). Si no hay uno adecuado, agregarlo con nombre y docblock; nunca un literal inline.
- **El fade de bordes:** `mask-image` no existe en RN. Portarlo con dos gradientes superpuestos en los bordes usando el color del pozo del ticker (`FIJOS_SPEC.tickerWellBackground`), que es lo que ya se usa en este repo para el mismo efecto. Si el resultado no convence contra el mockup, decirlo en el reporte en vez de improvisar otra técnica.
- **Reduced motion:** el ticker se detiene y el pulso no corre. Con la lista quieta, el contenido no debe quedar cortado a la mitad — arrancar en `0` es lo correcto.

- [ ] **Step 3: Los 6 estados (A1–A6)**

Igual que el hero: una prop discriminada. A1 con avisos (`worried`) · A2 sin aumentos (`think`) · A3 nada por pagar (`think`) · A4 todo tranquilo (`cheer`) · A5 urgente (`sad`, anillo durazno en la card, pill del contador en rojo) · A6 sin fijos (`wave`).
