# Sistema de i18n (ES-LATAM + EN)

> Doc canónico del sistema de internacionalización. **Contrato para los agentes
> de extracción**: leelo entero antes de tocar copy.

## Stack
- `i18next` + `react-i18next` + `expo-localization`. Locales: **`es`** (default + fallback)
  y **`en`**. Solo 2 idiomas.
- Init: `mobile/lib/i18n/index.ts`. Resolución de idioma: `mobile/lib/i18n/locale.ts`.
- Provider: `mobile/features/preferences/language-provider.tsx` (espeja `theme-provider`:
  sistema por defecto + override ES/EN persistido en `persistent-kv`).
- Toggle en Ajustes (Settings → "Idioma"). Sync a `profiles.preferred_language`
  vía `useLanguageSync` (para push notifications server-side).

## Cómo se usa en un componente
```tsx
import { useTranslation } from 'react-i18next'

function MyComponent() {
  const { t } = useTranslation()
  return <Text>{t('home:hero.title')}</Text>
}
```
- Fuera de React (helpers puros), importar la instancia: `import i18n from '@/lib/i18n'`
  y usar `i18n.t('ns:key')`. Evitarlo en hot paths; preferí pasar el string ya resuelto.

## Namespaces (un JSON por namespace y por idioma)
`mobile/lib/i18n/locales/{es,en}/<namespace>.json`. Namespaces:
`common · states · auth · errors · onboarding · home · gastos · fijos · control ·
settings · billing · garden · achievements · insights · notifications`.

**Cada área es DUEÑA de su namespace.** Un agente edita SOLO su namespace (es+en) y
SOLO los archivos de su subtree. NUNCA tocar `resources.ts`, `index.ts`, ni el JSON
de otro namespace. Así el fan-out es paralelo sin colisiones.

### `common` = glossary + acciones genéricas (referencia obligatoria)
- `common:terms.*` — terminología canónica (Gasto→Expense, Gasto fijo→Fixed expense,
  Día de cobro→Payday, Disponible→Available, Historial→History…). **Usá estos términos
  para mantener consistencia ES↔EN.** Si tu copy usa uno de estos términos, referenciá
  `t('common:terms.expense')` en vez de escribir "Gasto"/"Expense" suelto.
- `common:actions.*` — Guardar/Cancelar/Volver/Reintentar/Continuar/Eliminar… Reusá
  estas en vez de duplicar.

## Convenciones de keys
- Nombres en **camelCase**, anidados por pantalla/sección: `home:hero.title`,
  `gastos:filters.all`, `settings:account.signOut`.
- El **valor ES** debe ser EXACTAMENTE el copy actual (no reescribir el español).
- El **valor EN** lo escribís vos, traducción natural (no literal), tono igual de
  cercano/claro que el ES, usando los términos del glossary.
- No traducir: identificadores, keys de objetos, strings de log/console, valores de
  enum, nombres de archivo, claves de analítica. Solo copy USER-FACING.

## Interpolación
ES tiene `` `Faltan ${n} días` `` → key con `{{var}}`:
```json
{ "payday": { "countdown": "Faltan {{days}} días" } }   // es
{ "payday": { "countdown": "{{days}} days left" } }       // en
```
```tsx
t('control:payday.countdown', { days })
```

## Pluralización (NO portar el ternario ES)
ES usa `${n===1?'mes':'meses'}`. En i18next se usa el plural CLDR:
```json
// es
{ "months": { "ago_one": "Hace {{count}} mes", "ago_other": "Hace {{count}} meses" } }
// en
{ "months": { "ago_one": "{{count}} month ago", "ago_other": "{{count}} months ago" } }
```
```tsx
t('insights:months.ago', { count: months })
```
- Pasá SIEMPRE `count`. i18next elige `_one`/`_other` por idioma (EN y ES comparten
  la regla one/other, pero NO hardcodees el plural en el valor).

## Variantes por persona (control-signals-copy.ts)
Usá el `context` de i18next (framing = `loss` | `gain` | `neutral`):
```json
{ "recoveryHard_loss": "...", "recoveryHard_gain": "...", "recoveryHard": "..." }
```
```tsx
t('insights:recoveryHard', { context: framing, ...args })
```
El sufijo vacío (`recoveryHard`) es el default/neutral.

## Worklets de Reanimated
**Prohibido `t()`/`Intl` dentro de un worklet** (crashea el UI runtime). Si una
animación necesita texto, precomputá el string en el JS thread y pasalo ya resuelto.
(Los worklets actuales son solo numéricos — no deberías encontrarte con esto.)

## Accesibilidad
`accessibilityLabel` / `accessibilityHint` user-facing TAMBIÉN se traducen, en la
misma pasada. `accessibilityRole` no (es un enum).

## Formatters (NO los toques en la extracción)
Número/fecha/moneda viven en `mobile/lib/i18n/formatters.ts` (tarea aparte). No
reimplementes formateo; si encontrás `Intl.NumberFormat('es-AR'…)` o `.toLocaleString('es-AR')`
en TU archivo, dejalo anotado en tu reporte pero no lo migres acá.

## Reglas para los agentes (resumen)
1. Editá SOLO los archivos de tu subtree asignado + tu namespace JSON (es+en).
2. NO toques `resources.ts`, `index.ts`, otros namespaces, ni archivos fuera de tu lista.
3. Reemplazá cada string user-facing hardcodeado por `t('tuNamespace:key')`.
4. ES = copy literal actual. EN = traducción natural con el glossary.
5. Interpolación `{{var}}`, plurales CLDR (`_one/_other` + `count`), personas con `context`.
6. Mergeá keys en tu JSON: NO sobreescribas keys ya existentes (otro paso pudo agregarlas).
7. NO corras `tsc` repo-wide (verás ediciones a medias de otros agentes). Verificá tu
   propia lógica; el typecheck global lo corre el orquestador al cerrar la ola.
8. Reportá: archivos tocados, # strings extraídos, y cualquier string que dejaste sin
   migrar (cross-área, worklet, formatter) con file:line.

## Verificación de 100%
Lint AST (`scripts/guard-i18n-hardcoded.mjs`, tarea de infra) que falla si hay copy
user-facing fuera de `t()`. Más QA visual en ES y EN, light+dark.
