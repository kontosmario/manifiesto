Resumen ejecutivo:

- Galería persistente en `Settings → Tu progreso → Logros` con hero progress + dots strip + sectioned earned/locked.
- Dev preview (sin tocar DB) en `Settings → Desarrollo → Preview · Logros & Racha` — emitter singleton del que el Bridge subscribe en paralelo al realtime.

### Streak — estados visibles

El `StreakFlameIcon` renderea según `StreakData`:
- **Activa** (varios niveles por `currentStreak`): Arranque (1-7) → Constante (8-14) → Disciplinado (15-29) → Imparable (30-59) → Maestro (60-99) → Leyenda (100+). Cada nivel cambia la paleta del fuego y la intensidad de la animación (breath / flicker / inner-dance / pulse-ring / dim-pulse). Web cae a estado estático por limitaciones de Reanimated v4 en web.
- **En riesgo** (`!hasLoggedToday && !isBroken`): tono más frío, anillo de pulse-dim. Si `freezeTokens > 0` muestra el escudo.
- **Rota** (`isBroken`): gris, sin animación; el `longestStreak` se conserva para mostrar el récord.

**Para previsualizar los 9 estados**: el dev preview screen renderea una grilla 3×3 con celdas etiquetadas (Activa·Arranque, ..., En riesgo · 1 escudo, Rota).

**Trigger de reapertura**: ≥500 MAU + Bucket B (monetization / RevenueCat) activo. Antes no tiene sentido — el costo del LLM-proxy edge function (~$126/mo a 5K MAU para Tier 1.1 con Haiku 4.5) no se justifica sin revenue stream.

**Arquitectura propuesta** (cuando se reabra): edge function `llm-proxy` que toma `{ promptKey, vars, userId }`, fetcheia el prompt template versionado, llama a Anthropic API, cachea el resultado en `assistant_llm_cache` con TTL razonable según tipo de señal, devuelve al cliente. Esto permite (a) versionar prompts sin redeploy de la app, (b) absorber spikes de costo con caching agresivo, (c) trackear quality metrics por prompt version.
